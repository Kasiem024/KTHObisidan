Hur kommunicerar vår klient app med databasen? Finns alltid ett API som är specifikt för den databasen. Problemet är att för olika SQL databaser så ser det olika ut eftersom det finns olika SQL dialekter.

ODBC (Open Database Connectivity), samma API för olika databashanterare.

JDBC (Java Databse Connectivity), samma API för olika databashanterare.

För vår lab kommer vi skriva koden i Java med sql API. Vi behöver en JDBC-driver. Den översätter det som vi skriver i Java över nätet så att vi kan faktiskt kommunicera med vår databas. Måste ladda ner driver för att kunna göra labben. Finns olika driver för olika DBMS.

---

## Komponenter i JDBC

Driver manager - Laddar rätt dirvutin om den finns på systemet och skapar en connection.

Connection - Representerar en session med databasen. Kommunikation sker via denna connection.

Statement/PreparedStatement/CallableStatement - Används för att exekvera SQL-kommandon. Fås från Connection-objektet.

Result-Set - Representerar resultatet av en SQL fråga.

---
Våran applikation får inte agera som användaren root. Den representerar en super användare, en användare som har total kontroll. Våra användare ska istället representera klient appen med begränsade rättigheter. Man måste skapa denna användare.

---

## PreparedStatment

PreparedStatment ska användas då en specifik sats exekveras ofta (som en cache). Används också för att skydda mot SQL-injection.

Satsen kompileras första gången den exekveras och kan ”återanvändas” tills den uttryckligen stängs (eller sessionen avslutas, via conn.close())

Man kan, och bör, använda paramterar till PreparedStatment.

---

## Felhantering

SQLException.

Checked exceptions, dvs. `throws` eller `catch` (kan inte ignoreras i koden)

Viktigt att allokerade resurser frigörs oavsett om fel uppstår eller ej. Om det inte går att hantera felet i metoden ska den kastas vidare och hanteras i den anropande metoden med `throws`.

---

## Explicita Transaktioner

En transaktion är flera satser som hör ihop. Antingen så körs alla eller inget händer.

Håll koll på auto-commit.

### Abstract Coupling

När man programmerar har delar upp koden, där varje del kommunicerar med varandra. Low coupling handlar om att de olika delarna ska känna så lite om varandra som möjligt.
